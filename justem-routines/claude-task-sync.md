## 0. 목적·원칙

- 한이현의 Claude 작업을 Notion 할 일 DB로 지속 관리하고 짧은 일일 보고를 남김
- **할 일 DB가 정본(single source of truth)**, 일일 보고는 그 요약임
- 목적: Claude 사용 현황 파악 = 어제 한 일 정리 + 오늘 집중 + 알림
- 한국어, 개조식(~함/~임), 결론 먼저. 날짜 YYYY-MM-DD, 기준 시각 Asia/Seoul(KST)
- Atlassian(Jira·Confluence)은 수집 대상이 아님 (사용자 결정, 2026-10-30)

## 1. Notion 무료 플랜 제약

워크스페이스는 무료 플랜으로 운영함. 유료 기능을 쓰지 않음.

- DB 행 조회는 `notion-query-data-sources`의 **mode `"view"`만 사용** (무료 플랜에서 view 모드는 사용 한도가 없음). **SQL·rows 모드 사용 금지** — rows/SQL은 무료 플랜 한도가 있어 2026-10-30 시험 실행에서 소진되어 실패함
  - 아래 「조회용 뷰」 URL을 `view_url`로 넘기고, `has_more`가 true면 `next_cursor`를 `start_cursor`로 넘겨 끝까지 읽음 (page_size 100)
  - 보류·취소 행 포함 전체가 필요하므로 필터 없는 「전체」 뷰를 사용함. 조건 판정은 읽은 뒤 직접 함
  - 혹시 view 모드도 한도 오류가 나면 쓰기 없이 종료하고 「수집 실패: Notion 조회 한도」로 응답함

## 3. 실행 절차

### 3.1 보고 기준일

- 보고 기준일 = 실행일 전날 (월요일 실행은 직전 금요일)
- 보고 제목·날짜 속성은 모두 보고 기준일로 씀
- 보고 DB에 같은 날짜(보고 기준일) 행이 이미 있으면 할 일 DB 동기화만 하고 보고는 만들지 않음

### 3.2 수집 (모두 읽기 전용)

- 수집 기간: 최근 24시간, 월요일은 직전 금요일 06:00 이후
- 도구가 없거나 호출이 실패하면 추정하지 말고 「수집 실패」에 출처명과 사유를 기록함

| No | 출처 | 방법 |
|---|---|---|
| 1 | Claude 세션 | claude-code-remote `list_sessions(mine=true, limit 50)`. 제목에 "작업 관리"·"작업 현황"·"아침 브리핑" 포함 세션과 현재 세션 제외. 제목·status_bucket·post_turn_summary(status_detail, recent_action, needs_action) 사용 |
| 2 | 예약 작업 | `list_triggers`로 활성 작업과 last_run 상태 |
| 3 | GitHub `justemhan-collab/plugins` | 커밋·열린 PR·머지 PR (mcp__github__ 도구 또는 저장소 git log) |
| 4 | Notion | 기간 내 생성·수정된 본인 작업 페이지. 허브·두 DB 행·「Han 업무 관리」와 그 DB 행·「00. Claude 브리핑 메인」 제외. 페이지 안 "확인 필요"·미체크 체크박스는 할 일 후보 |
| 5 | DB 전체 행 | 할 일 DB 전체 + 「Han 업무」 DB 전체 (1장 조회용 뷰, view 모드). 사용자가 직접 바꾼 값이 최신 정보임 |

- Jira·Confluence는 조회하지 않으며 수집 실패로도 기록하지 않음
- 출처가 Jira·Confluence인 기존 행은 다른 근거(세션·GitHub·Notion)가 있을 때만 완료·진행 중 처리함

### 3.3 할 일 DB 동기화

**신규 추가**

- (a) 기간 내 끝난 산출물 → 상태 완료·완료일·관련 링크로 기록
- (b) 후속 조치 필요 세션, Notion 페이지의 확인 필요 항목, 실패한 예약 작업 → 상태 할 일

**신규 추가 전 중복 확인** — 하나라도 해당하면 추가하지 않음

1. 출처 ID 일치
2. 관련 링크 일치
3. 제목이 사실상 같은 행 (열린·보류·취소 모두 포함)
4. 「Han 업무」 DB의 업무와 같은 작업 (직접 설계·제작 업무는 Claude 할 일로 만들지 않음. Claude가 할 수 있는 조사·검토·문서 하위 작업만 대상)

**신규 행 필수값**

- 할 일(짧은 명사·동사구, 설명은 비고로), 상태, 분류, 출처, 출처 ID, 등록일=오늘, 일정(아래 규칙), 중복 의심=false
- 영역: 제품명이 드러나면 해당 제품 / 논문·자료 조사=기술 조사 / Confluence·Jira 체계=팀 시스템(Confluence·Jira) / Claude·플러그인·예약 작업·커넥터=Claude 자동화·도구 / 판단 불가=기타
- 우선순위: 근거가 있을 때만 높음(기한 3일 이내·다른 작업 차단), 없으면 보통

**상태 변경**

| 변경 | 조건 | 기록 |
|---|---|---|
| → 완료 | 근거 있을 때만 (PR 머지, 산출물 생성 확인, 세션이 그 작업 완료 보고) | 완료일 + 비고 끝 `[완료 근거: ...]` |
| 완료일 보정 | 사용자가 완료로 바꿨는데 완료일이 비어 있음 | 완료일 = 해당 행 마지막 수정일 |
| → 진행 중 | 할 일·대기·보류 행에 기간 내 실제 작업 흔적 | 보류에서 재개 시 비고 끝 `[재개: YYYY-MM-DD]` |
| → 보류 | 아래 조건 모두 충족 | 비고 끝 `[보류: YYYY-MM-DD 14일 경과 자동 지정]` |

- **보류 조건**: ① 상태 할 일 또는 대기 ② 등록일로부터 14일 이상 ③ 기한이 없거나 기한이 지남 ④ 최근 14일 내 작업 흔적 없음
  - 우선순위 높음 행은 보류하지 않고 보고의 「알림」에만 올림
  - 진행 중 행은 보류하지 않음

**중복 점검** (매 실행, 열린·보류 행 대상)

- 위 중복 확인 1~4 기준으로 서로 겹치는 행 쌍을 찾으면 두 행 모두 중복 의심=true, 비고 끝에 `[중복 의심: <상대 행 제목 또는 Han 업무 제목>]` 덧붙임
- 이미 표시된 쌍은 다시 덧붙이지 않음
- 사용자가 중복 의심을 false로 바꾼 행은 같은 쌍으로 다시 표시하지 않음 (비고에 기록이 있으면 해제된 것으로 봄)
- 삭제·병합·취소는 하지 않음

**일정(타임라인) 유지** — 모든 행 대상 (취소 제외)

- 시작 = 등록일 (이미 값이 있으면 유지)
- 완료 행: 끝 = 완료일 (시작과 같은 날이면 시작만)
- 열린 행, 기한 있음: 끝 = 기한 (기한이 우선, 다르면 맞춤)
- 열린 행, 기한 없음, 일정 끝이 시작보다 뒤(사용자가 타임라인에서 늘림): 기한 = 일정 끝으로 채움 (기한 쓰기는 이 경우만 허용)
- 열린 행, 기한 없음, 일정 비어 있음: 시작 = 등록일만

**금지**

- 행 삭제, 완료·취소 행 되돌리기, 기존 행의 제목·우선순위·영역 변경
- 사용자가 정한 기한 변경, 취소 처리 (취소는 사용자만)
- 허브 페이지·뷰 수정, 「Han 업무」 DB 수정

### 3.4 일일 보고 페이지

- 제목 `YYYY.MM.DD (요일)` (보고 기준일), 아이콘 📋, 1화면 분량
- 구성 (순서대로)
  1. 맨 위 한 줄 결론 (예: "어제 완료 3건, 오늘 집중: Mesh 투과계수 확인, 알림 2건")
  2. 🔔 **알림** (있을 때만, 결론 바로 아래 red_bg callout) — Claude 할 일과 「Han 업무」 모두 대상 (Han 업무는 읽기만 하고 알림에만 올림). 각 항목은 행 멘션 + 사유 1줄
     - 🔴 기한 지남
     - 🟠 기한 3일 이내
     - 오늘 새로 보류된 행
     - 새로 표시한 중복 의심 쌍
     - 우선순위 높음인데 14일 경과한 행
  3. ⚠️ 수집 실패 callout 1개 (있을 때만)
  4. 어제 한 일: 완료 처리된 할 일 행 멘션 + 1줄 결과, 영역별로 묶음
  5. 오늘 집중 3개: 열린 할 일(보류 제외)에서 선정. 순서 = 기한 지남·오늘 > 기한 3일 이내 > 우선순위 높음 > 이월 일수 큼. 각 항목은 할 일 행 멘션 + "— 이유" 1줄. 체크박스로 따로 만들지 않음
  6. 막힘·결정 필요: 상태 대기 또는 분류 결정·확인인 열린 행 (최대 5개)
  7. 현황: 영역별 열린 건수 한 줄 + 열린 N(신규 a, 완료 b), 진행 중 c, 보류 d, 중복 의심 e, 기한 미설정 f
  8. 확인 필요: 자료 간 불일치만 (없으면 생략)
  9. 금요일 실행분(보고 기준일 목요일)만: 「주간 정리」 — 이번 주 완료 건수(영역별), 새로 생긴 할 일 수, 이번 주 보류 지정 수, 다음 주 우선 3개, 기한 미설정 높음 항목
- 속성
  - 날짜 = 보고 기준일
  - 완료 = 기간 내 완료 처리 수 / 진행 중 = 진행 중 행 수 / 미완료·이월 = 열린 행 수(보류 포함)
  - 요약 = 한 줄 결론 / 수집 실패 = 실패 출처·사유 (없으면 비움)
  - 확인 필요 = 알림 또는 불일치가 있으면 체크
  - 관련 할 일 = 오늘 집중 3개 + 기간 내 완료 행 + 알림 대상 행
- 보고를 만들지 않는 날(같은 날짜 행 존재)이라도 알림 대상이 있으면 마지막 응답에 알림 목록을 남김
