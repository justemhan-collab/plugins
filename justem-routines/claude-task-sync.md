## 0. 목적·원칙

- Claude 작업은 「Claude 작업관리」에서, 직접 업무는 「Han 업무 관리」에서 관리함
- 매 평일 아침 두 페이지를 읽어 **Claude 작업 DB를 최신으로 맞추고**, 완료된 행을 각 페이지의 「완료 항목」 DB로 옮긴 뒤, 두 영역을 합친 **짧은 일일 보고 1건**과 **푸시 알림**을 남김
- 목적: 어제 한 일 정리 + 오늘 집중할 것 + 기한·입고 알림
- 한국어, 개조식(~함/~임), 결론 먼저. 날짜는 YYYY-MM-DD, 기준 시각은 Asia/Seoul(KST)
- Atlassian(Jira·Confluence)은 수집 대상이 아님

## 1. Notion 무료 플랜 제약

워크스페이스는 무료 플랜으로 운영하며 유료 기능을 쓰지 않음.

- DB 행 조회는 `notion-query-data-sources`의 **mode `"view"`만 사용**. SQL·rows 모드는 사용 금지 (무료 한도가 있어 2026-10-30에 소진된 적 있음)
  - 아래 조회용 뷰 URL을 `view_url`로 넘김. `has_more`가 true면 `next_cursor`를 `start_cursor`로 넘겨 끝까지 읽음 (page_size 100)
  - 조건 판정은 읽은 뒤 직접 함
  - view 모드도 한도 오류가 나면 쓰기 없이 종료하고 「수집 실패: Notion 조회 한도」로 응답함
- `notion-search`는 query만 사용함. filters와 sort 옵션은 쓰지 않음
- 차트·대시보드 뷰, 자동화, 동기화 DB 등 유료 기능은 만들거나 고치지 않음

### 2.1 Claude 「작업」 DB 속성 (Claude가 쓰는 열)

- 작업(제목)
- 진행 상태: 시작 전 · 진행 중 · 완료 · 보관 (보관 = 취소, 사용자만 지정)
- 우선순위: 높음 · 중간 · 낮음
- 등록일, 시작일, 마감일, 완료일
  - 시작일 = 진행 중으로 바뀐 날. 시작 전 행은 비워 둠
- 영역: 기술 조사 · 팀 시스템(Confluence·Jira) · Claude 자동화·도구 · 기타
- 비고, 관련 링크
- 템플릿에서 온 열(담당자·태그·프로젝트·선행/후속/상위/하위 작업)은 쓰지 않음
- 「완료 항목」(Claude) 열: 작업, 진행 상태, 우선순위, 등록일, 시작일, 마감일, 완료일, 영역, 비고, 관련 링크 (작업 DB와 같은 이름·옵션)

### 2.2 「장기 보류」 DB 속성

- 프로젝트(제목), 진행 상태(백로그 등), 우선순위, 등록일, 보류 지정일, 영역, 비고, 관련 링크

### 2.3 Han 「작업」 DB 속성 (읽기만)

- 작업(제목), 진행 상태(시작 전 · 진행 중 · 완료 · 보관), 우선순위
- 시작일, 마감일, 입고예정일
- 태그(JPB · JFS · JDM · J-STB · 단품 · 팀 운영 / 설계 · 구매 · 회의), 프로젝트(관계), 비고
- 비고에 「PUPOReq…」 번호가 있거나 태그에 「구매」가 있으면 구매 건으로 봄
- 「완료 항목」(Han) 열: 위와 같음 + 완료일. 프로젝트 관계는 프로젝트 DB의 「완료 작업」 열과 짝을 이룸

### 2.4 일일 보고 DB 속성

- 제목, 날짜, 주차(select — 없는 옵션은 update-data-source로 **기존 옵션을 모두 유지하며** 추가)
- 완료, 진행 중, 미완료·이월, Han 알림(number), 요약, 확인 필요(checkbox), 수집 실패
- 관련 작업(Claude 「작업」 DB 관계). 「관련 할 일」 열은 옛 DB 연결이라 쓰지 않음

### 2.5 사전 확인

- 처음 작성하기 전에 `notion://docs/notion-flavored-markdown-spec`을 fetch로 1회 읽음
- 작업 전 Claude·Han 「작업」 DB와 두 「완료 항목」 DB를 fetch해 최신 속성·옵션을 확인함 (사용자가 바꿨을 수 있음). 속성 이름이 이 문서와 다르면 실제 이름을 따르고 보고 「확인 필요」에 적음

## 3. 실행 절차

### 3.1 보고 기준일

- 보고 기준일 = 실행일 전날 (월요일 실행은 직전 금요일)
- 보고 제목·날짜 속성은 보고 기준일로 씀. 알림 판정 기준일은 **실행일(오늘)**
- 일일 보고 DB에 같은 날짜 행이 이미 있으면 동기화만 하고 보고는 만들지 않음

### 3.2 수집 (모두 읽기 전용)

- 수집 기간: 최근 24시간. 월요일은 직전 금요일 06:00 이후
- 도구가 없거나 호출이 실패하면 추정하지 않고 「수집 실패」에 출처명과 사유를 기록함

| No | 출처 | 방법 |
|---|---|---|
| 1 | Claude 세션 | claude-code-remote `list_sessions(mine=true, limit 50)`. 제목에 "작업 관리"·"작업 현황"·"아침 브리핑"이 들어간 세션과 현재 세션은 제외. 제목·status_bucket·post_turn_summary 사용 |
| 2 | 예약 작업 | `list_triggers`로 활성 작업과 last_run 상태 |

| 4 | Notion | 기간 안에 생성·수정된 본인 작업 페이지. 「Claude 작업관리」「Han 업무 관리」와 그 하위 DB 행, 0.bak 하위, 「00. Claude 브리핑 메인」은 제외. 페이지 안의 "확인 필요"·미체크 체크박스는 할 일 후보 |
| 5 | DB 전체 행 | 1장 조회용 뷰 7개 전부 (view 모드). 사용자가 직접 바꾼 값이 최신 정보임 |

### 3.3 Claude 「작업」 DB 동기화

**신규 추가**

- (a) 기간 안에 끝난 산출물 → 진행 상태 완료, 완료일, 관련 링크
- (b) 후속 조치가 필요한 세션, Notion 페이지의 확인 필요 항목, 실패한 예약 작업 → 진행 상태 시작 전

**신규 추가 전 중복 확인** — 하나라도 해당하면 추가하지 않음

1. 관련 링크가 같은 행 (Claude 작업·완료 항목·장기 보류 모두)
2. 제목이 사실상 같은 행 (완료 항목·보관·장기 보류 포함)
3. 비고의 `[출처: …]` 값이 같은 행
4. Han 「작업」 DB의 업무와 같은 작업. 직접 설계·제작·구매 업무는 Claude 작업으로 만들지 않음. Claude가 할 수 있는 조사·검토·문서 하위 작업만 대상

**신규 행 필수값**

- 작업: 짧은 명사·동사구. 설명은 비고에 씀
- 진행 상태, 등록일 = 오늘, 영역
- (a) 완료 산출물로 추가하는 행은 시작일 = 산출물 작업을 시작한 날(근거 없으면 완료일과 같게)
- 비고 끝에 `[출처: 세션 ID / PR 번호 / 페이지 URL 등]` (중복 판정 키)
- 영역: 논문·자료 조사 = 기술 조사 / Confluence·Jira 체계 = 팀 시스템(Confluence·Jira) / Claude·플러그인·예약 작업·커넥터 = Claude 자동화·도구 / 판단 불가 = 기타
- 우선순위: 근거가 있을 때만 높음(기한 3일 이내, 다른 작업을 막음). 없으면 중간

**상태 변경**

| 변경 | 조건 | 기록 |
|---|---|---|
| → 완료 | 근거가 있을 때만 (PR 머지, 산출물 생성 확인, 세션의 완료 보고) | 완료일 + 비고 끝 `[완료 근거: …]` |
| 완료일 보정 | 사용자가 완료로 바꿨는데 완료일이 비어 있음 | 완료일 = 그 행의 마지막 수정일 |
| → 진행 중 | 시작 전 행에 기간 안의 실제 작업 흔적이 있음 | 시작일 = 그날 + 비고 끝 `[진행: YYYY-MM-DD 근거]` |
| 시작일 보정 | 진행 중인데 시작일이 비어 있음 (사용자가 직접 바꾼 경우 포함) | 시작일 = 비고의 `[진행: …]` 날짜, 없으면 그 행의 마지막 수정일 |

- 자동 보류는 하지 않음. 장기 보류 DB로 옮기는 것은 사용자가 함 (3.4의 후보 알림만 올림)

**금지**

- 행 삭제·이동, 완료·보관 행 되돌리기, 보관 지정
- 기존 행의 제목·우선순위·영역·마감일 변경
- 장기 보류 DB, 0.bak, 페이지 본문·뷰 수정
- Han 업무 관리 행의 값 수정 (3.6 이동과 이동 뒤 완료일·프로젝트 복원만 허용)

### 3.4 알림 판정 (기준일 = 실행일)

**Claude 작업** (진행 상태 완료·보관 제외)

- 🔴 마감일 지남 / 🟠 마감일 3일 이내
- 🟤 장기 보류 이동 후보: 시작 전 + 등록 30일 이상 + 마감일이 없거나 지남 + 최근 30일 작업 흔적 없음. 우선순위 높음은 후보로 올리지 않고 🔴/🟠만 적용

**장기 보류 DB**

- 등록 30일을 넘긴 건수만 현황에 적음. 개별 알림은 하지 않음

**Han 업무** (진행 상태 완료·보관 제외, 읽기만)

### 3.5 일일 보고 페이지

- 제목 `YYYY.MM.DD (요일)` (보고 기준일), 아이콘 📋, 한 화면 분량

  2. 🔔 **알림** (있을 때만, red_bg callout) — 「Claude 작업」과 「Han 업무」 두 묶음으로 나눔. 각 항목은 행 멘션 + 사유 1줄
  3. ⚠️ 수집 실패 callout 1개 (있을 때만)
  4. **어제 한 일**: Claude 「완료 항목」 중 완료일이 기간 안인 행(영역별) + Han 「완료 항목」 중 완료일이 기간 안인 행(태그별, 읽은 값 그대로). 3.6에서 이번에 옮긴 행 포함. 행 멘션 + 결과 1줄
  5. **오늘 집중 3개**: Claude 작업과 Han 업무의 열린 행에서 고름. 순서 = 마감·입고 지남 > 3일 이내 > 우선순위 높음 > 시작일(등록일)이 오래된 순. 각 항목은 행 멘션 + "— 이유" 1줄. Han 업무가 들어가면 앞에 [Han] 표시
  6. 📦 **이번 주 입고 예정**: Han 업무 중 입고예정일이 이번 주(월~일)인 행. 날짜순, 지난 것은 「확인 필요」 표시
  7. **막힘·결정 필요**: Claude 작업 중 비고에 [대기]가 있거나 「결정」「여부」가 제목에 든 열린 행 (최대 5개)
  8. **현황**
     - Claude: 열린 N(신규 a, 완료 b) · 진행 중 c · 마감 미설정 d · 장기 보류 e건(30일 경과 f)
     - Han: 열린 N · 진행 중 c · 입고 대기 g · 프로젝트별 열린 건수
  9. **확인 필요**: 자료 사이의 불일치만 (없으면 생략)
  10. 금요일 실행분(보고 기준일 목요일)만 「주간 정리」: 이번 주 완료 건수(Claude 영역별, Han 태그별), 새로 생긴 Claude 작업 수, 다음 주 마감·입고 예정, 다음 주 우선 3개
- 속성
  - 날짜 = 보고 기준일, 주차 = 「YYYY년 M월 N주차」
  - 완료 = Claude 「완료 항목」 중 완료일이 기간 안인 수
  - 진행 중 = Claude 작업 진행 중 수
  - 미완료·이월 = Claude 작업 열린 행 수
  - Han 알림 = Han 업무 알림 건수
  - 요약 = 한 줄 결론, 수집 실패 = 실패 출처·사유 (없으면 비움)
  - 확인 필요 = 알림 또는 불일치가 있으면 체크
  - 관련 작업 = 오늘 집중·완료·알림에 나온 Claude 작업 행 (완료 항목으로 옮긴 행도 같은 페이지이므로 그대로 넣음)
- 같은 날짜 행이 이미 있어 보고를 만들지 않는 날도 알림이 있으면 마지막 응답에 알림 목록을 남김

### 3.6 완료 행 이동 (「작업」 → 「완료 항목」)

사용자 또는 3.3이 진행 상태를 「완료」로 둔 행은 각 페이지의 「완료 항목」 DB로 옮김. 3.3 동기화가 끝난 뒤, 3.5 보고 작성 전에 함.

- 대상: Claude 「작업」·Han 「작업」에서 진행 상태 = 완료인 행. **보관 행은 옮기지 않음**
- 같은 날짜 보고 행이 있어 보고를 만들지 않는 날도 이동은 함
- 순서 (행마다)
  1. 행을 fetch해 프로젝트 관계와 마지막 수정 시각(page_last_edited_at)을 기록
  2. `notion-move-pages`로 `data_source_id` = 해당 「완료 항목」으로 이동 (한 번에 최대 100행)
  3. 이동 뒤 값 복원·기록
     - 완료일이 비어 있으면 1의 마지막 수정일(KST 날짜)
     - Han: 프로젝트 관계를 1에서 기록한 값으로 다시 넣음 (이동하면 관계가 빠짐)
     - Claude: 시작일이 비어 있으면 비고의 `[진행: …]` 날짜, 없으면 등록일
- 이동 실패 시 원래 DB에 그대로 두고 「수집 실패」에 행 이름과 사유를 적음
- 완료 항목 행을 다시 「작업」으로 되돌리는 일은 사용자가 함 (되돌린 행이 완료가 아니면 다시 옮기지 않음)

## 4. 공통 규칙

- **쓰기 허용 범위**: Claude 「작업」 DB 행 추가와 3.3의 진행 상태(진행 중·완료)/시작일/완료일/비고 수정, 3.6 완료 행 이동과 이동 뒤 완료일·시작일·프로젝트 복원, 일일 보고 DB 행 1개 생성, 주차 옵션 추가
- 그 외 금지: 메일·메시지 발송(6장의 카카오톡 나에게 보내기는 예외), git push, Han 업무 관리·장기 보류·0.bak·다른 Notion 페이지 수정, 이 지시서 파일 수정
- 개인정보·비밀번호·인증키·고객 민감 수치는 적지 않음. 세션은 제목·요약 수준으로만 적음
- 근거 없는 추정 금지. 자료 사이의 불일치는 「확인 필요」로만 보고함
- Notion 도구를 쓸 수 없으면 아무것도 쓰지 말고 마지막 응답 첫 줄에 "Notion 연결 실패"와 수집 내용을 남김

## 5. 마지막 응답 (푸시 알림 본문)

알림이 있거나 수집 실패가 있으면 PushNotification으로 보냄. 알림·실패가 모두 없으면 보내지 않음.

1. 첫 줄: 알림 건수와 가장 급한 1건 (Claude·Han 통틀어)
2. Han 입고·마감 알림 목록 (있을 때)
3. 보고 페이지 URL (만들지 않았으면 사유)
4. 한 줄 결론
5. Claude 작업 DB 변경 내역: 추가 n · 완료 처리 n · 진행 중 변경 n · 완료일 보정 n · 시작일 보정 n / 완료 항목 이동: Claude n · Han n
6. 수집 실패 출처 목록
7. 읽은 지시서 경로와 버전 (예: origin/main, v2.2)

## 6. 카카오톡 보고 (확인 필요·실패 사항)

사용자가 지속적으로 업데이트할 예정이므로, 손봐야 할 데이터와 실패 사항을 카카오톡 「나에게 보내기」로 보냄.

- 보낼 때: 아래 항목이 하나라도 있으면 매 실행 끝(보고 페이지 작성 후)에 보냄. 모두 없으면 보내지 않음
  - **확인 필요**: 3.5-9의 자료 불일치, 2.5의 속성 이름 불일치, Han 업무 「입고 확인 필요」(입고예정일 지남), 비고에 「확인 필요」가 적힌 열린 행
  - **실패**: 3.2 수집 실패, Notion 쓰기 실패, 3.6 이동 실패, 지시서 읽기 실패·버전 낮음, 보고를 만들지 못한 사유
- 형식: 메시지 1건은 **200자 이하**. 넘으면 「확인 필요」와 「실패」로 나누어 최대 3건까지 보냄
  - 첫 줄 `[Claude 작업 보고 MM.DD] 확인 필요` 또는 `… 수집 실패` (MM.DD = 보고 기준일)
  - 항목은 `1) …` 번호 붙여 한 줄씩, 행 이름과 사유만 짧게. 마지막 메시지 끝에 보고 페이지 URL
  - 개인정보·인증키·고객 민감 수치는 넣지 않음
- 카카오톡 도구가 없거나 전송이 실패하면 다른 쓰기는 그대로 두고, 보고 페이지 「수집 실패」와 5장 마지막 응답에 「카카오톡 보고 실패: 사유」를 적음
- 지시서를 못 읽어 Notion에 쓰지 않고 종료하는 경우에도, 카카오톡 도구가 있으면 「지시서 읽기 실패」 1건은 보냄
